# 网关请求路径

本文说明一次网关请求（`src/gateway.rs` 的 `handle_inner`）在数据库和缓存上的开销，以及为了让它不随数据量变慢所做的设计。不改变任何产品行为。

一次普通请求依次经过：

| 步骤 | 说明 |
| --- | --- |
| 鉴权 | 按 Key 哈希读取 Key 及其限制，已撤销或停用的 Key 被拒绝 |
| 限额检查 | 每日 Token、每日费用、总费用合成一条查询，只在 Key 设了限额时执行 |
| 并发排队 | 按 Key 的并发上限取信号量许可 |
| 候选渠道 | 读取可路由的渠道并排序（不缓存，见下文） |
| 价格 | 读进程内缓存，不查库 |
| 写用量 | 记录 `usage_events`；流式请求结束后补充用量和费用 |
| 健康状态 | 只在成功清零或失败时更新 |

## 价格表缓存

- `AppState` 中缓存价格表，`state.prices()` 返回 `Arc<Vec<ModelPrice>>`，读的时候不复制。
- `pricing::start_refresh` 在启动时加载，之后每 30 秒重读一次，作为漏刷新时的兜底。
- 所有修改价格的地方（价格保存、OpenRouter 同步、模型目录的新增、修改、删除）保存后立即刷新缓存。
- 后台接口仍直接读库，它们不在请求路径上。

缓存失效的最坏情况是 30 秒内用旧价格算费用。

## 限额检查

### 一条查询

每日 Token、每日费用和总费用查的都是同一个 Key 的 `usage_events`，只是时间范围不同，所以合成一条查询，用 `FILTER` 区分：每日部分从今日起点与每日重置时间（`usage_reset_daily_at`）中较晚的那个开始，总费用从总重置时间（`usage_reset_total_at`）开始。三个限额都没设的 Key 不查。错误码和提示文案见 [Key 持有者自助](key-holder-design.md#网关错误原因码)。

时间边界在 SQL 里计算（`date_trunc('day', now())`），不放到 Rust，否则「今日」的起点会从数据库时区变成进程时区。

### 什么时候检查

- 能立即拿到并发许可时，只在持有许可后检查一次。
- 拿不到许可、需要排队时，先检查一次，已经超额的请求直接失败，不进入排队；拿到许可后再检查一次，防止排队期间额度被用完。

持有许可时检查，使同时越过限额的请求数以 Key 的并发上限为界，而不是以同时到达的请求数为界。限额不预留进行中请求的费用，不是精确的硬上限。

### 覆盖索引

迁移 `0067_usage_key_limits_idx.sql`：

```sql
CREATE INDEX usage_key_limits_idx ON usage_events(account_id, virtual_key_id, created_at)
  INCLUDE (cost_usd, input_tokens, output_tokens, status, in_flight_until);
```

限额查询可以只扫索引，不用组合两个单列索引再回表。

不用 `CONCURRENTLY`：迁移在新版本开始服务之前执行，而中断的并发建索引会留下一个 INVALID 索引，下次启动重跑 `CREATE INDEX` 时因同名而失败。

代价：`INCLUDE` 的列被更新时不能走 HOT 更新。流式请求结束后补充费用和用量会受影响，使 `usage_events` 膨胀略快。

不做累计费用字段：它需要处理流结束后费用被改写和重置时间的边界，复杂度高；等 `usage_events` 大到覆盖索引不够用时再考虑。

## 不缓存的部分

- 候选渠道不缓存。渠道的 `enabled`、密钥和健康状态都要求立即生效，缓存几秒就违反「路由必须尊重 enabled」的约定，而这条查询本身走索引、量很小。
- 鉴权和限额不合成一条 SQL：错误要区分「Key 无效或停用」和「额度用完」，合在一起难写难读，省下的只是一次往返。

## 并发上限即时生效

`AppState` 按 Key 保存 `(Arc<Semaphore>, usize)`。取信号量时比较上限，不同就新建一个替换旧的。旧信号量已经发出的许可由持有者继续持有到请求结束，所以调小上限后的短时间内总并发可能超过新值，之后收敛；调大立即生效。不用 `add_permits`/`forget_permits` 原地修改，因为 `forget_permits` 只能回收当前空闲的许可，调小时不能保证生效。

Key 被撤销后从 map 中删除对应条目，避免 map 只增不减。

由于并发控制保存在进程内存中，OpenVAIR 只能单实例运行，见 [部署与运维](../self-hosting.md#限制)。

## 测试

单元测试覆盖价格缓存（保存后立即可见、刷新失败保留旧值）和信号量（上限变化后新建、不变时复用）。

数据库测试（`src/gateway_db_tests.rs`，通过 `scripts/test-model-management.sh` 运行）覆盖：每日 Token、每日费用、总费用和费用未确定暂停各自触发，错误码和文案正确；重置时间生效；改价格后下一次请求用新价格记账；调大 Key 的并发上限后第二个并发请求不再排队；新索引存在。
