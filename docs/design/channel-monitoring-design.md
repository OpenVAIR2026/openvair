# 渠道监控设计（v2：独立模型监控）

## 资源与操作

可用性监控仍按渠道管理。质量监控是一项独立资源，每项固定对应当前帐号的一个渠道和一个具体公开模型。同一渠道、模型只能有一项未删除的监控；模型不能包含通配符。模型解析与网关一致：渠道映射、已启用的模型路由、原模型名依次回退。

质量页提供添加、编辑、手动检测、详情和删除。创建时选择渠道与模型，默认关闭定时、仅观察，并勾选“保存后立即检测”。停用渠道仍可保存配置，但不能立即检测；API 省略 `run_immediately` 时仅在渠道启用时立即检测，对停用渠道显式传 `true` 返回 409。渠道和模型在创建后固定，更换对象必须新建监控，避免混淆历史。

创建、配置、运行和删除均写入帐号审计日志。所有用户可访问的读写均通过渠道校验 `account_id`。

## 配置

| 字段 | 含义和范围 | 默认值 |
| --- | --- | --- |
| `schedule_enabled` | 是否定时执行；关闭仍可手动检测 | false |
| `interval_seconds` | 定时周期，900–86400 秒 | 3600 |
| `methods` | arithmetic / json / instruction / context，至少一项、不重复 | 全部 |
| `timeout_ms` | 单题超时，10000–180000 毫秒 | 60000 |
| `round_timeout_ms` | 整轮时限，不小于单题超时，最大 720000 毫秒 | 240000 |
| `min_score` | 最低通过分数，0–100 | 75 |
| `failure_threshold` | 连续答题失败确认次数，1–5 | 2 |
| `daily_run_limit` | 每个 UTC 自然日的排队轮次预算，0–10000；0 不额外限制 | 0 |
| `route_policy` | observe / deprioritize / exclude | observe |

次数预算包含手动、定时、首次检测以及失败、取消的任务，任务入队时计数。同一监控的重复请求复用活动任务，不重复计数。每轮最多调用所选方法数次。此预算不表示美元费用上限；旧的未执行金额预算仍保存在旧配置表中，不转换成次数预算。

## 执行、状态与路由

- 手动接口返回 `202` 和 `job_id`。任务先持久化入队，页面自动刷新排队、运行和结果状态。
- 后台每 5 秒调度到期监控，每批最多 20 个；单进程最多执行 4 个任务。PostgreSQL 行锁、活动任务唯一索引和租约避免重复调度与跨进程重复认领。
- 请求只使用模拟题目。凭证由现有加密存储解密使用，不进入运行记录或审计内容；响应体最多 1 MiB，完整回答不保存。
- 四项确定性检查验证算术、JSON、指令遵循和单条消息内的短文本回指。它们是基础行为检查，不能证明整体模型能力。v2 算术严格匹配 `21`，不接受负数、小数或仅在文本中出现正确数字。
- 所选题目全部完成后才产生分数，分数为通过比例。HTTP、解析、凭证和超时错误产生未知观测，不作为答题失败计数，也不清零已有失败计数。
- 达到失败确认次数后，模型状态变为 `degraded`；一次完整通过恢复 `healthy`。最近观测与确认状态分别保存，页面显示疑似回退、确认回退、未完成或过期。
- 完整观测有效期为当前周期的两倍；修改检测周期时，按新周期重新计算现有结论的有效期。定时是否到期以数据库时间为准。仅在确认回退且结果仍有效时执行降权或剔除；只影响对应渠道的公开模型。降权将该渠道排到未降权候选之后，仍可用作备选。
- 首次检测、未知且无有效结论、结果过期时不因质量监控阻断路由。可用性、渠道启停与 Key 启停仍按网关原有规则生效。
- 关闭定时取消自动任务，保留手动任务、历史和路由策略；页面说明结果过期后自动路由限制解除。总览只对定时监控提示「质量待确认」「质量已过期」，仅手动监控不提示，确认回退仍会提示。停用渠道取消活动任务并清除当前结论，重新启用后按原定时设置安排新检测。
- 修改方法、评分或超时配置会增加配置版本并重新验证。渠道映射或旧路由接口改变上游模型时也会使旧结论失效。删除采用软删除，取消后续任务、立即停止该监控的路由影响，保留历史。旧任务只能写入带 `applied=false` 的历史，不能覆盖新配置的状态。
- 进程崩溃后的运行任务在租约到期后标记失败；排队任务可由重启后的进程继续认领。定时检测配置错误或预算不足会记录原因并退避重试。

## 数据与迁移

迁移 `0032_model_quality_monitors.sql` 新增：

- `quality_monitors`：目标、配置、独立健康快照、有效期、配置版本和软删除时间。
- `quality_monitor_jobs`：任务来源、状态、租约、配置版本及时间。
- `channel_monitor_runs.monitor_id`：关联独立监控；旧版渠道汇总记录保持 NULL。

已有质量配置按去重后的模型拆分，继承方法、频率、超时和阈值。已开启的旧配置迁移为定时开启、自动剔除；已关闭但有已配置模型或历史的配置迁移为仅手动、仅观察。默认未配置过质量检测的渠道不自动创建监控。

模型回退顺序为配置列表、旧单模型、测试模型、渠道首个模型、映射公开名、路由公开名。没有可解析模型的配置保留在旧表中，需要手动添加监控。

旧渠道规则可能是 `demo-*` 这类前缀，`0032` 会把它当作监控模型，导致监控永远无法探测。迁移 `0035_model_management_corrections.sql` 把这类监控的配置转移到该渠道首个具体名称（旧单模型、测试模型、渠道规则、映射公开名、路由公开名），渠道已有具体监控时不再新建，然后软删除前缀监控并取消其任务。此后有效监控的模型不能包含 `*`。

旧渠道总分不复制为模型健康结论。新监控从未知开始，单独检测后建立状态。路由语义也由旧版“必须健康且未过期”调整为“仅对有效的确认回退执行策略”，因此迁移期间未知模型可以参与路由；上线前应了解这项有意调整。

旧配置和旧健康字段保留以便审计，新代码不再读取它们作为质量路由依据。删除监控不会删除历史，当前未设置自动清理期限。数据库迁移仅向前执行；旧程序虽可读取旧表，但回滚后会恢复旧的渠道级策略，不应把回滚视为语义兼容。

## API

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/quality-monitors` | 当前帐号未删除的监控、模型映射、状态和最近任务状态 |
| POST | `/api/quality-monitors` | 创建监控，可同时排队首次检测 |
| PATCH | `/api/quality-monitors/{id}` | 更新检测配置，渠道和模型不可修改 |
| DELETE | `/api/quality-monitors/{id}` | 软删除，停止任务与路由影响，保留历史 |
| POST | `/api/quality-monitors/{id}/run` | 手动排队，与定时开关无关；返回 202 |
| GET | `/api/monitoring/runs?kind=quality&monitor_id=&page=&limit=` | 帐号范围历史，支持指定监控，包含已删除监控 |
| GET | `/api/monitoring/summary` | 可用性渠道摘要 |
| GET / PATCH | `/api/channels/{id}/monitor` | 可用性配置 |
| POST | `/api/channels/{id}/check` | 立即检查可用性 |

旧的渠道级质量运行入口移除，可用性配置接口拒绝质量字段，避免旧客户端静默修改无效配置。

创建示例：

```json
{
  "channel_id": "渠道 UUID",
  "model": "公开模型名",
  "run_immediately": true,
  "settings": {
    "schedule_enabled": false,
    "interval_seconds": 3600,
    "timeout_ms": 60000,
    "round_timeout_ms": 240000,
    "methods": ["arithmetic", "json", "instruction", "context"],
    "min_score": 75,
    "failure_threshold": 2,
    "daily_run_limit": 24,
    "route_policy": "observe"
  }
}
```

## 验证

- `cargo fmt --all`
- `cargo clippy --locked --all-targets -- -D warnings`
- `cargo test --locked`
- `bash scripts/test-quality-monitor.sh`：独立临时 PostgreSQL、模拟渠道与本地拦截上游，退出清理数据库。
- `npm --prefix web ci && npm --prefix web run build`
- `npm --prefix web run test:monitoring`：Playwright 浏览器测试，使用模拟 API；需要已安装 Playwright Chromium。

数据库测试覆盖迁移、租户隔离、手动运行、预算、幂等任务、开关与渠道恢复、并发认领、模型级路由及配置/删除竞争。浏览器测试覆盖添加、映射显示、编辑定时、手动执行、删除、详情链接及桌面/窄屏布局。
