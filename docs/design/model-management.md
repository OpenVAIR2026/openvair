# 模型管理、匹配与计价

## 管理边界

- 管理员统一维护标准模型目录、协议和独立价格，入口为「系统管理 → 模型管理」。每个完整模型 ID 一条记录，身份创建后不可修改。隐藏只影响目录展示，不等同于禁止调用，已配置价格仍用于计价。
- 「添加模型」合并 OpenRouter 参考目录与现有系统目录，按完整 ID 去重。可按 ID、显示名称模糊搜索，忽略大小写、常见分隔符，支持空格分隔多个关键词；搜索不改变模型 ID 的精确身份。列表显示已加入 / 未加入，已加入（含已隐藏）不可勾选；全选只选择当前搜索结果中的未加入模型，切换搜索保留选择。确认后批量新增，默认启用、支持现有默认协议并保持待定价，价格在加入后单独设置或同步；目录未覆盖的模型仍可手动添加。
- 批量添加前重新读取目录，跳过此期间已被加入的模型（如另一个浏览器标签页），写入只调用新增接口，不覆盖已有名称、协议、隐藏状态或价格。部分成功时立即更新已加入状态，保留失败项选择以便重试；加载目录失败时禁用批量添加。
- 渠道可配置目录外具体名称和别名，别名对应哪个上游模型由渠道映射决定。配置和调用这些名称不会自动加入系统目录，但会作为该渠道的已知名称出现在模型列表中。
- 系统目录只收录具体模型 ID，不再管理前缀模板：目录接口拒绝新建或修改带 `*` 的条目，列表也不返回早期迁移写入的前缀条目（数据保留以兼容回滚，不参与计价、目录数量或客户端模型列表）。前缀规则只在渠道和 API Key 的模型输入框中填写：下拉建议只列具体模型，前缀规则通过下方「添加前缀规则」按钮或直接输入 `gpt-*` 后回车添加。
- 创建、编辑表单获取上游模型仅作为当前连接的填写候选，无需确认收录。获取到的名称写入渠道规则或映射后才会出现在模型列表中；需要对所有渠道展示和计价的新名称，由管理员加入系统目录。

## 规则与路由

| 对象 | 模式 | 行为 |
| --- | --- | --- |
| 渠道 | `allowlist` | 至少一条精确名称或前缀规则，显式模型映射也可接受对应别名 |
| 渠道 | `passthrough` | 接受该渠道协议下的具体名称，仍支持显式别名映射 |
| API Key | `allowlist` | 至少一条精确名称或前缀规则 |
| API Key | `all` | 允许全部具体名称，实际调用仍须有可用渠道；不保存规则 |

渠道表单在「模型规则」旁提供「全部转发」勾选项：勾选为 `passthrough`，不勾选为 `allowlist`。Key 表单在「允许模型」旁提供「允许全部模型」勾选项，对应 `all` 与 `allowlist`。

Key 还可限定接入的渠道（迁移 `0040_virtual_key_channels.sql`）。`channel_mode` 为 `all` 时使用帐号下全部渠道，新建 Key 默认如此，已有 Key 迁移后也保持 `all`；为 `selected` 时只路由到 `virtual_key_channels` 中的渠道，模型路由、映射和 `/v1/models` 列表都只看这些渠道，停用、异常和降级渠道仍按原规则跳过。选择 `selected` 至少需要一个本帐号渠道；编辑时省略 `channel_mode` 保留原设置。删除渠道会同时移除关联，所有渠道都被删除的 Key 不会回退到全部渠道，列表提示「未接入可用渠道」。表单先选渠道再设允许模型，候选模型来自所选渠道；规则在所选渠道中无法匹配时提示但不自动删除。

每日 Token、每日费用和总费用在表单中通过「添加限制」按需加入，移除即保存为不限；每分钟请求数和并发上限是固定字段。列表只为已设置的限制显示进度条，其余用量以文字显示。

仅支持完整名称或一个末尾 `*`，区分大小写，如 `demo-chat`、`demo-*`。不支持裸 `*`、中间通配符、正则和通配模型请求。规则只做允许/不允许判断，多条规则命中等价。

候选排序沿用模型质量降权、路由优先级、渠道优先级和渠道密钥顺序；精确、前缀、全部转发均不增加排序权重，也不作为同优先级的决胜条件。停用、撤销、渠道健康和质量门禁继续生效。

模型输入框提供两个不同动作：

- 「添加当前匹配的 N 个模型」保存以输入内容开头（区分大小写，与前缀规则口径一致）的候选具体名称快照，不随未来目录扩展。
- 「添加前缀规则」保存持续生效的前缀，未来符合前缀的具体名称也会被允许。

直接回车保存原始输入；只有主动选择候选，才采用候选值。离开输入框不会添加未确认的文字，只提示按回车添加。空输入框按退格键只撤销本次编辑中刚添加的规则，不会删除已保存的规则。清空规则不会变成全部转发或全部权限，必须显式切换模式。获取上游模型不覆盖已配置规则、映射或模式；修改地址、协议或凭据后，旧候选失效。

全部转发和仅前缀规则的渠道必须指定具体测试模型。探测不会把前缀发送给上游；旧配置没有可探测名称时跳过探测，并保留上次健康状态。明确的模型不支持错误（含 Anthropic 404 `not_found_error` 且消息为 `model: …`）可尝试下一渠道；普通参数错误不会被当作模型不支持。

## 渠道表单与草稿测试

- 创建和编辑共用字段校验；模型映射必须填写完整的具体名称，对外名称不得重复。映射行使用稳定标识，输入时不重建控件。
- 表单「检查渠道／测试连接」和「获取上游模型」使用当前填写的参数，不要求先保存。编辑时省略 `secret` 或传空值，后端按当前帐号及 `channel_id` 读取已保存的启用凭据；提供新值则使用新值。预览不会写渠道配置、健康状态或模型候选。
- `POST /api/channels/preview-check` 与 `/api/channels/preview-models` 接受可选 `channel_id`；即使提供新凭据，也必须验证渠道归属。Key 不回传、不写审计元数据。
- 修改影响探测的参数后，表单中的检查结果失效；超过 14 分钟的检查结果也视为失效，保存时不再提交，需要重新检查。成功预览返回有效期 15 分钟的加密 `check_receipt`，绑定帐号、渠道（新建为空）、协议、地址、凭据及实际测试模型。创建或保存可以提交该结果，后端核验后记录健康状态与监控历史，并安排下一轮常规检查，不再立即重复请求上游。篡改、过期或配置不符时返回 400，事务不落库。
- 渠道列表的「检查」仍使用已保存配置并更新健康状态。修改已保存地址或凭据时清空旧上游候选；影响探测的配置变更使旧健康结果失效，匹配的成功预览可在保存时恢复健康状态。
- `PATCH /api/channels/{id}` 和 `/api/channels/{id}/models` 中省略 `test_model` 保留旧值，显式 `null` 清除。选填时默认使用按名称排序的首个具体规则，若存在映射则采用上游名称；全部转发或仅前缀规则不允许清空。
- 必要说明放在字段标题旁的信息图标弹层中，校验错误直接展示。Key 页面的引导横幅保留。

## 目录、数量和目录外调用

已知具体名称来源于启用的系统目录（按协议展开），以及渠道规则中写明的具体名称、映射别名和模型路由公开名（按渠道协议），并对名称去重；前缀规则和上游获取的候选不计入。渠道页面显示「指定模型数 / 前缀规则数」及「已知 N 个」，全部转发显示「全部转发」及已知目录数，不声称支持无限个模型，也不以规则条数冒充模型数。

`GET /v1/models` 和 `GET /v1beta/models` 只返回已知具体名称，经过当前 Key 权限和实际可路由渠道过滤；停用渠道、无启用上游密钥、不健康渠道不贡献可路由项；模型级质量监控只有在有效期内确认回退且策略为排除时，才排除对应模型，未知或过期结果放行。Key 列表的 `known_models` 使用相同口径。渠道的目录匹配数量是配置覆盖预览，不代表实时可用数量。

目录并非请求白名单。即使名称尚未加入系统目录，只要 Key 允许、有匹配协议的可路由渠道并通过计价校验，就可以调用。上游发现、渠道配置和成功调用均不会扩充目录或创建待确认记录。渠道写明的目录外名称和别名会列入 `/v1/models`、`/v1beta/models` 和已知模型数量，但没有目录价格时费用记为未知；仅由前缀规则或全部转发覆盖的名称需要客户端手动填写。桌面客户端允许选择没有列出模型的 Key 并手动输入模型名，连通检查遇到未列出的模型只提示、不判为失败。

## 精确计价和历史费用

计价链：请求名称 → 当前渠道映射 → 实际发送的完整上游模型 ID → 精确价格 → 调用时快照与费用。

例如请求 `team-chat` 经渠道映射为 `demo-chat-v2`，只使用 `demo-chat-v2` 的价格；不会使用 `team-chat`、`demo-*` 或 `demo-chat` 的价格。重试换渠道后，以最终使用渠道的具体上游名称计价。

每次记录保留请求名 `model`、上游名 `upstream_model`、三项单价 `price_snapshot`、费用 `cost_usd` 和计价状态：

| 状态 | 含义 |
| --- | --- |
| `priced` | 有价格快照和用量，费用可确认；明确的零价保持为零 |
| `unpriced` | 调用时该具体模型未定价，费用未知 |
| `pending_usage` | 有价格快照，但还没有完整用量；流式响应可继续补充 |
| `legacy` | 迁移前记录缺少必要快照，不能可靠追溯费用 |

改价、隐藏或删除目录项均不改变已记录费用。流式更新使用原始快照，并避免迟到更新覆盖更完整的用量。统计和 CSV 使用保存的费用；失败请求不产生费用，不计为费用未知。请求趋势的费用视图显示每个时段已计价的金额，含未计价请求的时段以琥珀色标出并在提示中说明条数。渠道表现显示已计价请求的金额合计，有未计价请求时在金额旁显示感叹号，悬停、聚焦或点击可查看模型及原因。全部未计价时显示零和感叹号，提示这些请求尚未计入。提示优先使用实际上游模型名，历史记录缺失时使用请求模型名；与金额沿用相同帐号、时间和筛选范围。其他费用汇总含未知请求时仍保留未知状态。

Key 创建、编辑表单在「每日费用上限」旁提供「费用无法确定时」，通过 `unknown_cost_policy` 独立选择：

| 策略 | 未定价的实际上游模型 | 当日已结束但费用未知的成功请求 |
| --- | --- | --- |
| `allow`（继续请求） | 允许调用并保留未知费用 | 不阻止后续调用；费用上限仅统计已计价金额 |
| `block`（暂停请求） | 跳过该候选，不发送上游；没有已定价候选可尝试时返回 409，未设费用上限时也生效 | 设有每日费用上限时，对该 Key 的新请求返回 409 |

两种策略都在已计价金额达到每日费用上限时拒绝新请求。未知费用不记为零、不参与费用合计；限额不预留进行中请求的费用，也不提供精确硬上限。模型权限和路由优先级不因该策略变化。暂停不会修改 Key 的启用状态或中断已有请求，错误信息说明拦截原因。

Key 另可设置「总费用上限」（`cost_limit_total_usd`），统计 Key 创建以来的已计价金额，达到上限后返回 429，调高或清空上限即恢复。未知费用门禁只按当日判断，不扩展到总上限：补充价格不会追溯计价历史请求，否则一条旧的未计价记录会永久暂停该 Key。编辑接口省略该字段时保留原值，传 `null` 才清除。每日 Token 和每日费用按 UTC 自然日（北京时间 08:00）重置。

管理员可在 Key 的「更多操作」中重置用量（`POST /api/keys/{id}/usage-reset`，`scope` 为 `today` 或 `all`）。重置只把限额统计的起点移到当前时间：`today` 写入 `usage_reset_daily_at`，今日 Token、今日费用和当日未知费用门禁从此刻重新计算，累计费用不变；`all` 同时写入 `usage_reset_total_at`，累计费用也从此刻起算。调用记录、使用分析和 CSV 不受影响；已撤销的 Key 不能重置，每次重置写入审计日志 `virtual_key.usage_reset`。

API Key 列表显示每个 Key 今日 Token、今日费用和累计费用相对上限的用量，达到 80% 标黄，达到上限标红并显示「已达上限」；有已结束但费用未知的成功请求时注明条数。使用分析支持按 Key 筛选（URL 参数 `key`），列表中的用量按钮直接跳转到对应 Key 的使用分析；已撤销但在所选时间范围内有请求的 Key 仍可选择，调用明细和 CSV 显示请求所属 Key。

使用分析的时间范围除近 24 小时、7 天、30 天外，还可选「全部时间」（URL 参数 `range=all`，概览页不提供）。全部时间从当前筛选条件下最早的一条请求开始，趋势图按跨度自动分桶：60 天内按天，420 天内按周，更长按 30 天，图表保持在约 60 根柱子以内。

OpenAI 流式请求始终设置 `stream_options.include_usage=true`，即使客户端传 `false`，以便计费；Gemini 未使用 `alt=sse` 的 JSON 数组流在结束后解析用量。流式请求的 `in_flight_until` 在上游返回成功响应头时记录。在正常结束、上游报错、客户端断开时，用原价格快照完成费用更新并清除标记，再释放并发名额；只有已结束仍无法计价的成功请求才触发未知费用门禁。标记使用与上游请求超时一致的 10 分钟期限，防止进程中断后永久忽略未结算记录。已有金额、部分用量更新和乱序保护继续生效。历史未知费用不会因补充今日价格而追溯改写。

## 接口与迁移

- `GET/POST /api/model-catalog`、`PATCH/DELETE /api/model-catalog/{id}`：统一模型与价格管理，写入仅管理员。新增元数据 `provider`、`protocols`，写入精确价格用 `price`，清空价格用 `clear_price: true`，两者不能同时提交。价格数值未变化时保留原价格来源。模型 ID 不可修改，修改时返回 400；`only_unpriced` 遇到已定价返回 409，模型不存在返回 404。
- `GET /api/available-models`：帐号当前可路由的已知具体名称。
- 渠道和 Key 创建/更新增加 `model_mode`。创建时省略默认为 `allowlist`；旧客户端若用空列表表示全部，需改为显式传 `passthrough` 或 `all`。更新省略模式则保留原模式，空规则不会扩大权限。Key 选择 `all` 时清空已保存规则；数据库把带规则却为 `all` 的写入改为 `allowlist`，防止发布预检或回滚期间不写模式的旧版本扩大权限。
- Key 启停使用 `PATCH /api/keys/{id}/enabled`（`{"enabled": bool}`），只修改开关，不会用旧列表数据覆盖其他设置；撤销的 Key 返回 404。
- Key 列表返回 `unknown_cost_policy`；创建省略或传 `null` 时默认为 `allow`，更新省略或传 `null` 时保留当前策略，只接受 `allow`、`block`。权限沿用管理员登录检查，撤销的 Key 无法修改。
- 待定价列表的「采用参考价」使用统一目录接口；已有目录项通过 `only_unpriced: true` 防止覆盖并发设置的价格，保留已有名称、协议和隐藏状态。
- 旧 `/api/platform/model-pricing` 接口为兼容保留，控制台不再调用其读写入口，字段 `pattern` 现在只接受具体模型 ID。POST 新增独立价格，已定价返回 409；PUT 仍为全量替换价格清单，未包含条目变为未定价。
- `/platform/model-pricing/unpriced` 汇总近 30 天实际上游模型，包含成功和失败调用、排除监控探测。旧价格确认界面及 `/platform/model-pricing/legacy` 接口已移除。
- OpenRouter 参考价仅用于管理员主动收录/同步，保留原有供应商命名转换；匹配转换后的完整 ID，字段缺失不能当作免费。按时段计价的报价（`pricing.overrides`，如 DeepSeek 高峰时段）取最贵的一档，一个价格无法跟随时段，按高峰价让费用上限偏保守。国产厂商（`src/pricing.rs` `FIRST_PARTY`：deepseek→DeepSeek、moonshotai→Moonshot AI、z-ai→Z.AI、qwen→Alibaba、minimax→Minimax、bytedance-seed→Seed，含 `~vendor/*-latest` 别名）的模型列表价常是第三方低价，改为逐个查询 `/models/{id}/endpoints`，只取厂商自营端点中最便宜的一个（区域端点更贵）；没有自营端点或查询失败时不给参考价，需手动按官方价填写，不退回第三方价格。顶部「同步参考价」通过 `GET /api/platform/model-pricing/sync-preview` 只读预览完整同名报价的差异，包含未定价的具体模型。侧栏展示当前与同步后价格，可多选或同步本次预览的全部差异，打开侧栏不会改价。
- `POST /api/platform/model-pricing/sync` 必须提交 `{changes: [...]}`，每项使用预览返回的模型 ID、当前价格、参考价及 `updated_at`；不再接受空请求直接全量同步。服务端重新核对参考报价，并在事务中锁定、校验所有所选目录记录。任一报价变化、目录修改或删除返回 409，整批保持不变，需要重新获取差异；不会应用预览之外的模型。
- 价格旁的图标仍调用 `/platform/model-pricing/sync-one`，允许给目录中尚未定价的具体模型补价。所有同步均不继承到变体，也不创建前缀价格；缺少完整同名参考价或请求失败时保留当前价格。

迁移 `0033_unified_model_management.sql` 保留渠道模式和路由优先级；旧 Key 非空规则回填为 `allowlist`，空规则回填为 `all`，维持原有权限。仅与既有具体目录 ID 完全相等的旧价格自动迁移，原 JSON 保留为后台归档。归档不参与新请求计价，不在日常管理页面要求确认；补录时需确认完整模型 ID，使用当前同名报价，不能从相似名称或前缀推断价格。旧用量保持 `legacy` 与未知费用，不按今日价格补造历史。

帐号模型与待收录功能及 `/api/account-models` 接口已移除。迁移 `0033` 创建的历史 `account_models` 表保留以兼容回滚，应用不再读写，历史记录不参与候选、目录或数量。无需执行删除表的迁移。

迁移 `0034_unknown_cost_policy.sql` 曾为已有费用限额 Key 设置 `block`。旧版本的费用限额会跳过未定价模型，因此迁移 `0035_model_management_corrections.sql` 把所有 `block` 恢复为 `allow`，保持原调用行为；需要暂停的 Key 由管理员显式设置。新 Key 默认 `allow`。已有使用记录的 `in_flight_until` 为 `null`，沿用已结束记录的判断，不补造用量或费用。

数据库迁移仅向前执行。发布前应核对实际使用模型的精确价格：旧版按前缀匹配的价格不再生效，这些模型的费用会变为未知、不计入费用限额，直到补录精确价格；改为 `block` 的 Key 在当日旧记录缺少费用时也会触发未知费用门禁。回退到 `0034` 之前的应用会忽略新策略并恢复与费用限额绑定的旧行为；回退到统一模型管理之前的代码还会使用旧价格 JSON，回滚前需确认价格、策略和模式兼容性。
