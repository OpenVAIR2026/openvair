# 请求详情与分段计时

使用分析的「调用明细」可点击整行，或用键盘激活模型名称，打开右侧请求详情。关闭后保留筛选、分页及列表位置，并将焦点还给入口。详情单独从 `GET /api/usage/events/{id}` 加载；接口沿用 `current_user`，事件和渠道名称查询均限制当前 `account_id`。其他帐号的记录返回 404。

Key 持有者自助页「用量 → 调用明细」（`/my-key/usage`）也可打开详情，仅显示当前 Key 的请求、计时、用量和费用，不展示渠道尝试。专用接口 `GET /api/key/events/{id}` 同时限制 `account_id` 和 `virtual_key_id`，以白名单返回汇总计时，不返回渠道标识、名称、尝试列表、上游模型和价格配置；响应使用 `Cache-Control: no-store`。暂停的 Key 可查看，撤销后不能访问。

## 计时口径

- `ttfb_ms`：网关接收请求到收到最终成功上游的响应头，包含鉴权、读取请求体、额度检查、并发排队、路由及前序尝试；不是纯粹的上游计算时间。
- `first_token_ms`：流式请求收到首个可识别输出的时间，包含文本、推理和工具调用。未识别到输出时保留 NULL，不拿响应头时间冒充首个输出。检测保留有限的跨网络分块后缀。
- `request_diagnostics.queue_ms`：等待调用方 Key 的并发信号量的时间。
- `attempts`：按顺序记录尝试的渠道 ID、相对请求开始的 `started_ms`、从发出尝试开始计量的 `headers_ms`、`first_token_ms` 和 `duration_ms`，以及 HTTP 状态与固定枚举结果。成功尝试的持续时间包含接收响应体；失败 HTTP 尝试包含读取错误响应体。
- 分布条的排队、前序尝试、最后尝试互不重复；剩余时间称为「其他处理」，包含网关鉴权、路由、数据库记录等未单独计时的工作。
- 「首个输出 → 结束」只对已经结束且记录了首个输出的流式请求计算。非流式请求显示收到响应头，不生成首个输出数据。

详情记录连接/发送失败、超时、HTTP 错误、响应中断和客户端断开。流式请求的 HTTP 状态在响应开始时已确定；收到 200 后仍可能中断，所以详情另外显示结束状态。未结束的详情每 3 秒刷新，关闭后停止；也可手动刷新。

目前仅覆盖网关已有的调用记录，鉴权失败、路由前拒绝及上游响应前客户端取消等未产生 usage event 的请求不新增记录。进程异常退出时无法补齐最终计时。没有存储上游内部排队、推理参数或 session ID，不据此推断模型内部耗时。

## 隔离与兼容

不保存请求/响应正文、请求头、上游地址、密钥或原始错误消息。调用方只看到自己帐号的渠道 ID。渠道名称在查看详情时按当前帐号解析，渠道已删除则明确显示已删除。

`0057_request_diagnostics.sql` 只增加可空 JSONB 列。历史记录保持 NULL，界面显示「未采集」，不补造计时；旧应用可以忽略此列，回滚应用不需要删除迁移。本改动不调整超时、重试或路由策略。

验证：`cargo fmt --all`、`cargo clippy --locked --all-targets -- -D warnings`、`cargo test --locked`、`bash scripts/test-model-management.sh`、`npm --prefix web ci`、`npm --prefix web run build`、`npm --prefix web run test:usage`。数据库测试使用独立临时 PostgreSQL、模拟上游和模拟凭据。
