# 上游报错的路由处理

路由是固定优先级加失败转移（`src/gateway.rs` 的 `load_routes` 和 `'routes` 循环），没有负载均衡和会话粘性。本文说明网关如何按上游报错的类型决定是否转移、是否计入渠道健康，以及 429 冷却和「系统管理 → 路由设置」。

不做负载均衡和会话粘性，是因为切换渠道会让提示词缓存命中率明显下降，而需要切换的请求只占很小一部分。

## 报错分类

真实请求和定时检查共用 `CheckKind::classify` 的分类，按分类决定三件事：

| 分类 | 判定 | 转移 | 计入健康 | 冷却 |
|---|---|---|---|---|
| 限流 | 429，且不是 `insufficient_quota` | 是 | 否 | **是** |
| 额度不足 | 402；429 `insufficient_quota`；400 "credit balance" | 是 | **是** | 否 |
| 密钥被拒 | 401、403 | **是** | **是** | 否 |
| 服务故障 | 5xx、408、连接失败、超时、首字超时 | 是 | 是 | 否 |
| 模型不支持 | 400/404 指明模型 | 是 | 否 | 否 |
| 请求错误 | 其他 4xx | 否，直接返回客户端 | 否 | 否 |

要点：

- 限流是唯一“渠道没坏、会自己恢复、只影响单个模型”的错误，用冷却短暂避开，不判故障、不发邮件。
- 额度不足和密钥被拒不会自己恢复，冷却没用。真实请求遇到时按 `Health::Rejected` 计入健康：沿用渠道的失败阈值（默认 2 次）判不可用，并发送告警邮件（需要配置发信邮箱），和定时检查一致。保留阈值，是为了避免个别请求特有的 403（如内容或地区限制）一次就把渠道判死。
- 密钥被拒时转移到其他渠道，避免客户端收到上游的 401/403，误以为是自己的 OpenVAIR Key 有问题。
- 判为不可用的渠道仍是“排到最后、不剔除”，所有渠道都失败时还会尝试。任意一次成功或定时检查成功即恢复。
- 所有渠道都失败时，返回给客户端的是最后一次的上游状态和错误体。

## 429 冷却

**写入**（收到限流分类的响应时）

- 冷却键 `meta-router:cooldown:{channel_id}:{upstream_model}`，带过期时间。按模型区分，因为上游限额通常按模型计算。
- 连续次数键 `meta-router:cooldown_strikes:{channel_id}:{upstream_model}`，过期时间为最长冷却时长的 2 倍。
- 冷却时长：
  - 开启“遵从 `Retry-After`”且上游给了该头：用它，限制在 5 秒到最长冷却时长之间。
  - 否则：`30 × 2^(连续次数 − 1)` 秒，最多到最长冷却时长。
- 该渠道该模型请求成功时，删除连续次数键。

**读取**

- 查出候选渠道后，对候选做一次 `MGET`，排序键为 `(不可用, 冷却中, 降级, 优先级)` 并稳定排序。
- 冷却中的渠道只排后，不剔除；全部在冷却时按原顺序尝试。
- Redis 出错或响应慢时视为没有冷却，路由不受影响。

Redis 使用共用的 `ConnectionManager`，限流与冷却不会在每个请求上新建连接。

## 路由设置

「系统管理 → 路由设置」（`GET/PATCH /api/platform/routing-settings`，仅管理员）。保存在 `system_settings` 的 `routing_settings` 键，值为 JSON。

| 设置项 | 默认值 | 范围 |
|---|---|---|
| 启用 429 冷却 | 开 | 开/关 |
| 最长冷却时长 | 300 秒 | 30–3600 秒 |
| 遵从上游 `Retry-After` | 开 | 开/关 |

- 首次冷却固定 30 秒，不开放。
- 没有记录时使用默认值。
- 保存时校验范围，越界拒绝。
- 网关不在每个请求上查表：设置缓存在 `AppState`，保存后立即刷新，并每 30 秒重读一次。

目前不开放：上游总超时、最多尝试渠道数、402 是否转移、可用性重查与告警时间、新建渠道默认值、会话粘性。

## 测试

`src/gateway_db_tests.rs`（模拟上游，不用真实 Key）覆盖：

- 限流：A 返回 429，下一个请求直接到 B，A 没收到请求；冷却到期后新请求回到 A。
- `Retry-After` 生效并被限制在范围内；关闭开关后按加倍规则。
- 连续限流时冷却加倍并封顶；一次成功后从 30 秒重新开始。
- 429 `insufficient_quota` 不进冷却，按额度不足处理。
- 所有渠道都在冷却：仍按顺序尝试，请求不会直接失败。
- 额度不足和 401/403：转移到 B，计入健康，连续达到阈值后 A 判为不可用。
- 其他 4xx：不转移。
- 关闭冷却、Redis 不可用：请求正常完成。
- 路由设置：非管理员无权读写；越界值被拒绝；保存后网关立即使用新值。
