# 控制台窗口交互规范

这份规范用于统一控制台新增功能的窗口形态，避免同一类任务在不同页面使用不同交互。

## 选择规则

- **侧拉窗口**：用于创建或编辑，需要填写多个字段、保留列表上下文，或包含测试、同步、映射等连续操作的任务。
- **确认弹窗**：用于删除、撤销、放弃未保存修改等需要用户确认的单一动作。
- **Toast 或页面状态提示**：用于保存成功、复制成功、同步完成、健康检查完成等短暂结果，不打断当前任务。
- **下拉菜单或小弹层**：用于选择模型、协议、状态等少量选项，不承载完整表单。

## 当前页面映射

| 任务 | 形态 |
| --- | --- |
| 添加渠道 | 右侧侧拉窗口 |
| 编辑渠道 | 右侧侧拉窗口 |
| 创建 API Key | 右侧侧拉窗口 |
| 删除渠道 | 确认弹窗 |
| 撤销 API Key | 确认弹窗 |
| 放弃未保存的渠道修改 | 确认弹窗 |
| 保存、复制、同步和检查结果 | Toast 或页面状态提示 |

## 统一视觉要求

- 侧拉窗口从右侧打开，标题栏固定，底部操作栏固定。
- 弹窗和侧拉窗口使用统一的标题字号、圆角、边框、描述文字和内容留白。
- 不在一个操作中嵌套第二个弹窗；需要继续编辑时回到当前侧拉窗口。
- 移动端侧拉窗口改为底部抽屉，确认弹窗仍保持居中。
