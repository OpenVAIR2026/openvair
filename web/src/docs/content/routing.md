## 怎么设置备用渠道

1. 添加两个或以上**协议相同**、模型规则都包含目标模型的渠道。
2. 主渠道「渠道优先级」设小值（如 `10`），备用渠道设大值（如 `20`）。

```text 示例
请求 claude-sonnet-5-5
  ① 官方 API（优先级 10）── 429 限流 ──┐
  ② 中转站 A（优先级 20）◀─────────────┘ 自动接手，返回结果
```

故障切换只在同协议渠道之间进行，见[协议必须一致](/docs/concepts#协议必须一致)。

## 什么情况会切换

| 情况 | 切换 |
| --- | --- |
| 连接失败 | 是 |
| 600 秒内未完成响应 | 是 |
| 流式请求超过「流式首字超时」无输出 | 是 |
| 开始输出前响应中断 | 是 |
| 429、402、408、5xx | 是 |
| 上游明确表示「模型不存在 / 不支持」 | 是 |
| 401、403（上游 Key 无效或无权限） | 否，直接返回 |
| 其他 4xx（如参数错误） | 否 |

![一次故障切换：第一个渠道返回 429，自动改用第二个渠道并成功](/docs-img/request-detail.webp)

所有候选渠道都失败时，返回最后一个渠道的错误。上游开始输出后，中途断开无法再切换。每次请求尝试了哪些渠道，见「调用明细」中的「渠道尝试」。

### 流式首字超时

流式请求在限定时间内没有任何输出（文本、推理、工具调用均算）时，放弃当前渠道改走下一个，客户端只收到下一个渠道的响应。

- 默认 100 秒，可在「渠道监控」中按渠道调整，范围 5–300 秒；与定时检查开关无关。推理模型思考较久，不宜设得过短。
- 最后一个候选渠道不切换，继续等待，直到有输出或达到 600 秒整体超时。

## 哪些渠道会参与

须同时满足：

- 协议与请求一致；
- 模型规则包含该模型、开启了全部转发，或配置了对应映射；
- 已启用；
- 未被[服务体检](/docs/monitoring#服务体检)的「剔除」策略排除；
- 在 Key 限定的「接入渠道」范围内。

## 排序规则

1. 判定「异常」且「判定异常后」为「移到路由最后」（默认）的渠道排在最后；设为「仅记录和告警」时保持原位；
2. 被服务体检「降低优先级」的渠道，排在正常渠道之后；
3. 「渠道优先级」数值小的在前；
4. 优先级相同时，先创建的在前。

异常渠道仍是候选，其他渠道都不可用时仍会尝试，监控误判不会让模型彻底不可用。

### 什么时候判定「异常」

连续失败达到设定次数（默认 2 次）即判定异常，任意一次成功清零。计入规则和复查间隔见[可用性监控](/docs/monitoring#判定规则)。
