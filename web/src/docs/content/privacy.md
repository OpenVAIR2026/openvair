所有数据保存在你自己服务器上的 PostgreSQL 和 Redis 中。OpenVAIR 只把请求转发给你配置的上游渠道，并通过「邮箱设置」中的发信邮箱发送验证码和告警，不向其他地方发送数据。

## 保存什么

### 请求数据

| 数据 | 是否保存 | 用途 |
| --- | --- | --- |
| 请求和响应正文（对话内容） | ❌ **不保存** | — |
| 模型名、协议、HTTP 状态、渠道 | ✅ | 使用分析、排查 |
| 耗时、首字时间、耗时分解、渠道尝试 | ✅ | 性能统计、请求详情 |
| Token 用量和费用 | ✅ | 额度、费用统计 |
| 输入字符数（不含内容） | ✅ | 计量检查 |
| 监控和检测结果 | ✅ | 渠道监控 |

用量记录不自动清理，需要时手动删除，见[部署与运维](https://github.com/OpenVAIR2026/openvair/blob/main/docs/self-hosting.md#数据增长)。

### 帐号和凭据

| 数据 | 是否保存 | 用途 |
| --- | --- | --- |
| 管理员登录邮箱、帐号名称 | ✅ | 登录、通知 |
| 登录密码 | ✅ 仅哈希 | 登录 |
| 登录设备的 User-Agent 和最近活动时间 | ✅ | 「登录设备」列表 |
| 操作日志 | ✅ 最近 200 条 | 帐号安全 |
| 上游供应商 Key | ✅ 加密 | 转发请求 |
| API Key | ✅ 哈希 + 加密副本 | 鉴权、再次复制 |

## Key 如何被保护

- **上游 Key**：AES-256-GCM 加密，密钥为服务器上的 `MASTER_KEY`，仅访问上游时解密；**永远不会**发送到任何客户端（控制台、桌面客户端、你的工具）。
- **API Key**：鉴权时比对哈希；加密副本仅在管理员点「复制」时解密，每次复制记入操作日志；**不会**转发给上游。
- 日志和错误信息中不出现完整 Key。

> [!IMPORTANT]
> 将 `MASTER_KEY` 与数据库备份分开妥善保存。缺少 `MASTER_KEY` 时，备份中的上游 Key 都无法解密。

## 安全建议

- **每人、每台设备独立一把 Key**，并[设置额度](/docs/limits)。
- **不要把 Key 写进代码或提交到 Git**。
- **可能泄露时立即撤销**，停用不会让旧 Key 失效，见[停用、重置和撤销](/docs/keys#停用重置和撤销)。
- **定期查看登录设备和[操作日志](/docs/account#操作日志)**。
- **通过 HTTPS 访问控制台**。登录 Cookie 默认仅经 HTTPS 发送（`COOKIE_SECURE=true`），公网上不建议关闭。
- **不受信任的人能访问控制台时**，在服务器设置 `ALLOW_PRIVATE_UPSTREAMS=false`，禁止渠道指向 `localhost`、内网 IP 或解析到内网的域名（默认允许）。
