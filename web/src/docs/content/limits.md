## 可以限制什么

| 限制 | 说明 | 恢复时间 |
| --- | --- | --- |
| 每分钟请求数 | 每个自然分钟的上限 | 下一分钟 |
| 并发上限 | 同时进行的请求数，超出的排队 | 前面的请求结束后 |
| 每日 Token | 输入加输出，单位**百万 Token** | 北京时间 08:00（UTC 0 点） |
| 每日费用 | 美元 | 北京时间 08:00（UTC 0 点） |
| 总费用 | 创建或上次重置以来累计（美元） | 不自动恢复 |

后三项在创建或编辑 Key 时，于「用量限制」点「添加限制」添加。

![创建 Key 时在「用量限制」里添加每日 Token 上限](/docs-img/key-create.webp)

## 费用是怎么算的

费用 = 上游返回的 Token 用量 × 配置的模型单价（[使用分析 → 模型单价](/usage?prices=1)）。

- 按实际调用的上游模型名精确匹配价格，[模型映射](/docs/models#模型映射)按映射后的名字计价。
- 分时段计价的厂商（如 DeepSeek 工作日高峰价翻倍）统一按高峰价估算。
- 每次请求保存当时的价格，之后调价不影响旧记录。
- 模型未定价或上游未返回用量时，不计费，也不计入费用上限。
- 费用都是**估算值**，以供应商账单为准（折扣、缓存计费、汇率等会造成差异）。

> [!IMPORTANT]
> 额度在请求**开始前**检查，进行中的请求不会被打断，费用不预扣，因此可能略微超限。例如每日上限 $5、已用 $4.9 时发起大请求，最终可能达到 $5.3。

## 达到上限时

客户端收到 429（模型无权限为 403），错误码和提示见[问题排查](/docs/troubleshooting#按错误码查找)。立即恢复：编辑 Key 调高上限，或在 Key 行点「重置今日用量」（总费用需「重置全部用量」）。

## 查看用量

- 「API Key」列表显示每把 Key 的今日 Token、今日费用和累计费用，达到 80% 变黄，100% 变红。
- 「更多操作」（⋯）→「查看用量」打开按该 Key 筛选的「使用分析」。

## 推荐设置

| 场景 | 建议 |
| --- | --- |
| 自己的电脑 | 不设，或较大的每日费用 |
| 分给同事、朋友 | 每日费用 + 总费用，限定模型 |
| CI、自动化脚本 | 每分钟请求数 + 每日费用 |
| 对外公开的应用 | 全部设置 |
