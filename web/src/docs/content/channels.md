## 添加渠道

1. 「上游渠道」→「添加渠道」。
2. 「渠道来源」：官方服务选「官方 API Key」并选厂商（自动填协议和 Base URL）；其他服务选「第三方 API Key」。
3. 选**协议**，填写表单。
4. 点「测试连接」，通过后点「创建渠道」。

![添加渠道表单](/docs-img/channel-create.webp)

> [!IMPORTANT]
> 协议创建后不能修改，选错需删除重建。按**使用的工具**选协议，不按模型选，见[协议必须一致](/docs/concepts#协议必须一致)。中转站支持多种协议时，可用同一把上游 Key 为每种协议各建一个渠道。

### 表单各项

| 字段 | 说明 |
| --- | --- |
| 渠道名称 | 便于辨认 |
| Base URL | 末尾 `/v1` 可省略 |
| 上游 API Key | 加密保存，客户端无法获取 |
| 渠道优先级 | 越小越优先，默认 100，见[故障切换](/docs/routing) |
| 模型规则 | 见[模型名与映射](/docs/models) |
| 测试模型 | 测试和健康检查用；留空自动选择 |

| 供应商 | Base URL |
| --- | --- |
| OpenAI | `https://api.openai.com` |
| Anthropic | `https://api.anthropic.com` |
| Google Gemini | `https://generativelanguage.googleapis.com` |
| 中转站 | 其文档给出的地址，如 `https://api.example.com/v1` |
| 本机或内网服务 | 如 `http://192.168.1.20:8000` |

默认允许 `localhost`、内网 IP 和解析到内网的域名；服务器设置 `ALLOW_PRIVATE_UPSTREAMS=false` 后拒绝，报 `channel URL resolves to a private or reserved network`。

### 测试连接

向上游发一个只输出 1 个 Token 的真实请求，费用极少。结果有效 14 分钟；之后改了地址、Key、模型规则或测试模型需重新测试。

## 获取上游模型

点「模型规则」旁的「获取上游模型」，把上游列表中尚未包含的对话模型加入规则（向量、图片等模型不加入），已有规则不变。勾选「全部转发」时不改规则，结果只作测试模型候选。

- OpenAI 兼容和 Anthropic 读 `GET /v1/models`，Gemini 读 `GET /v1beta/models`。
- 部分 Anthropic 中转站返回 404，此时手动填写或勾选「全部转发」。

## 查看渠道状态

![渠道列表：健康状态、模型范围和优先级一目了然](/docs-img/channels-list.webp)

| 健康状态 | 含义 |
| --- | --- |
| 健康 | 正常参与路由 |
| 异常 | 连续失败达到设定次数，默认排到最后；一次成功即恢复。原因显示在状态下方 |
| 待检查 | 刚修改设置，尚未检查 |
| 需测试模型 | 只有前缀规则或开启全部转发，需指定测试模型 |
| 已停用 | 已手动停用 |

点「检查」立即检查；新渠道默认每 30 分钟自动检查。判定规则、频率和失败次数见[可用性监控](/docs/monitoring#可用性监控)。

## 编辑、停用和删除

- **编辑**：可改名称、地址、Key、优先级、模型规则和[模型映射](/docs/models#模型映射)。上游 Key 留空则沿用原值。
- **停用 / 启用**：点电源图标。停用后不参与路由，设置保留，适合临时下线。
- **删除**：渠道、上游 Key 和监控设置永久删除，历史调用记录保留。
