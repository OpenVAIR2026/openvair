「渠道监控」有两类主动检查：**可用性监控**查渠道能否连通，**服务体检**查「渠道 + 模型」是否缩水、篡改或虚报用量。主动检查用渠道的上游 Key 发真实请求，**会产生少量费用**，各设置处显示预估费用。另有不收费的[被动检查](#被动检查)。

## 可用性监控

定时发送只输出 1 个 Token 的请求，真实请求的成败也计入。新渠道**默认开启**，每 30 分钟一次。点「立即检查」随时检查，点状态旁的 ⓘ 看失败原因，「最近 12 次」可区分偶发抖动和持续故障。

![可用性监控：最近 12 次检查结果，异常渠道会被标出](/docs-img/monitor-availability.webp)

### 判定规则

- **计入失败**：定时检查未成功（含上游拒绝密钥 401–403）；真实请求遇到上游 5xx、超时、连接失败或首字超时。429、402 和其他 4xx 不计入。
- **判定异常**：连续失败达到设定次数；任意一次成功清零。关闭定时检查后只有手动检查会改变状态。
- **无结论**：上游 429、不提供测试模型、检查未发出。只显示在「最近一次检查」，不改变判定。异常后超过 2 倍检查频率（至少 1 小时）只有无结论、没有新失败时，判定作废，恢复正常路由。
- **测试模型**：未指定时用最近 7 天真实请求成功过的模型，没有则按名称取第一个。指定模型被拒时改用最近成功的模型重试，显示黄色 ⚠；更新测试模型后消失。
- **复查**：失败后 10 分钟复查，持续失败时按 10、20、40 分钟递增，不超过检查频率。
- **异常后**：默认**移到路由最后**（其他渠道都不可用时仍使用），或「仅记录和告警，不影响路由」，见[排序规则](/docs/routing#排序规则)。成功后自动恢复。

### 设置项

「渠道监控 → 可用性监控」→ 渠道行的「设置」：

![单个渠道的可用性设置](/docs-img/monitor-availability-settings.webp)

| 设置 | 说明 |
| --- | --- |
| 开启定时可用性检查 | 关闭后仍可手动检查，真实请求不再计入 |
| 检查频率 | 5 分钟–24 小时 |
| 连续失败几次后判定异常 | 1–5，默认 2 |
| 判定异常后 | 移到路由最后（默认）或仅记录和告警 |
| 流式首字超时（秒） | 5–300，默认 100 |

### 流式首字超时

超时无输出时切换到下一个渠道，始终生效，行为见[备用渠道与故障切换](/docs/routing#流式首字超时)。推理模型不宜设得过短。

## 服务体检

对一个渠道上的一个模型随机出题：

![服务体检：监控列表和每次检查的结果](/docs-img/monitor-quality.webp)

| 检查项 | 内容 |
| --- | --- |
| 回答完整性 | 复述随机口令、做随机加法 |
| 缓存重放 | 不是上次的旧答案 |
| 计量检查 | 用量虚高或隐藏系统提示词 |
| 工具调用 | function calling 是否正常 |
| 输出截断 | 是否被提前截断 |
| 流式输出 | 事件格式、完整性和用量上报 |

回答完整性失败直接判异常，其他项按通过比例判定。被安全策略或内容过滤拦截的记为未完成，不算失败。

计量检查对 Claude Opus 4.8–5.5（Messages 接口）和 GPT-5.6 Sol、GPT-6 Astra、GPT-6.1 Sol（Chat Completions 或 Responses 接口）精确比对：输入 Token 超出本地计数 30 Token 或 5%（取较大者）即异常。其他组合（如用 OpenAI 协议调 Claude）只能估算，固定开销超过 100 Token 判为疑似隐藏系统提示词，按比例虚报只能发现明显离谱的情况，结果标为「仅粗查」。

### 添加体检

1. 「渠道监控 → 服务体检」→ 添加监控。
2. 选择渠道和模型（创建后不可改）。
3. 设置定时检测频率（15 分钟–24 小时）。
4. 选择「路由影响」：

| 选项 | 效果 |
| --- | --- |
| 仅观察（默认） | 只记录 |
| 异常时降低优先级 | 排在正常渠道之后，仍作兜底 |
| 异常时剔除 | 不再参与该模型路由 |

连续失败达到「失败确认次数」（默认 2）才「确认异常」，路由策略随之生效。结果有效期为检测周期的 2 倍，过期后恢复正常路由。

### 长上下文检测

在体检详情中手动发起：在长文本随机位置藏口令，按 8k → 32k → 128k 测试实际可用的上下文长度。

> [!WARNING]
> 单次输入可达十几万 Token，费用较高，发起前会显示预估。

## 被动检查

分析最近 24 小时真实请求，发现用量虚报、隐藏系统提示词等**计量异常**。不发请求、不收费、不影响路由。

该模型有服务体检时，先提前运行体检确认再发[告警邮件](/docs/account#告警邮件)，24 小时内体检通过的项目撤销同类警告；用量虚报无法由体检确认，直接发出。
