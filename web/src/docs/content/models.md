## 模型规则

渠道的「模型规则」决定它提供哪些模型。

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| 具体模型名 | 只匹配该模型 | `gpt-4.1-mini` |
| 前缀 + `*` | 匹配该前缀开头的所有模型，含以后新增的 | `claude-*`、`gemini-2.5-*` |

- `*` 只能出现一次且在**末尾**；不支持单独的 `*` 或 `gpt-*-mini`。
- **区分大小写**：`gpt-*` 不匹配 `GPT-4.1`。
- 按回车或逗号添加；未按回车就离开输入框不会添加。
- 下拉框的「添加当前匹配的 N 个模型」逐个加入此刻匹配的模型；「添加前缀规则 xxx\*」以后自动包含同前缀新模型。

### 全部转发

勾选「全部转发」后，任何模型的请求都原样转给该渠道，由上游决定能否使用。

> [!WARNING]
> 全部转发的渠道接收所有同协议请求，优先级高时可能接走其他渠道的模型并报「模型不存在」。上游明确返回「模型不存在」时会切换到下一个渠道，但仍建议设较低优先级（较大的数值）。

## 模型映射

把**对外模型名**（客户端请求的名字）改写为**上游模型名**。只能在创建渠道后点「编辑」，在「模型映射」中添加。

![编辑渠道时设置模型规则和模型映射](/docs-img/channel-models.webp)

| 场景 | 对外模型名 | 上游模型名 |
| --- | --- | --- |
| 中转站命名不同 | `claude-sonnet-5-5` | `claude-5.5-sonnet` |
| 稳定别名 | `team-default` | `gpt-4.1-mini` |
| 多渠道共用一个名字 | `fast` | 官方渠道 `gpt-4.1-mini`，中转站 `claude-haiku-4-5` |

- 多渠道共用对外名时，故障切换后客户端仍请求同一名字；渠道协议必须相同。
- 对外名和上游名都必须是具体名称，不能带 `*`；同一渠道内对外名不能重复。
- 配置了映射的对外名，即使不在模型规则中，也会被该渠道接收。
- **费用按上游模型名计算**。

## Key 的模型权限

Key 的「允许模型」（写法同上，填**对外模型名**）和渠道规则都满足才会发出：

```text
请求 model = claude-sonnet-5-5
   ├─ Key 允许吗？  允许模型含 claude-*        ✓
   └─ 有渠道吗？    Anthropic 渠道规则含 claude-* ✓  → 发出
```
